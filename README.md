# 校园网守护 · 安卓版

**守在手机上的校园网小工，断了就自动接回来。**

深澜 SRun 校园网的断线自动**重新认证**工具。手机在校园网里掉线后，它会自己向门户重新登录一次，恢复成功记一条日志；网络本来就是通的，它就什么都不做。

纯 Java、零第三方依赖、不用 Gradle / AndroidX，10 个源文件约 7600 行、APK 约 158 KB。不 root、不装模块、不改系统网络设置，也不用重新输入 WiFi 密码。

## 1. 项目解决什么问题

手机连着校园网 WiFi，但门户的登录状态掉了——聊天软件转圈、网页打不开，得手动打开浏览器再登一次。一天掉几次，每次都要翻出那个 IP 和账号密码。

| 场景 | 现象 |
| --- | --- |
| 门户「踢下线」 | WiFi 图标正常、系统显示已连接，就是上不了外网 |
| 熄屏 / 待机 | 睡眠期间认证状态丢失，亮屏后才发现断网 |
| WiFi 抖动、漫游 | 短暂断开又连回，IP 变了、门户会话没了 |
| 宿舍断电、回寝 | 手机自动连上 WiFi，但从没认证过 |
| 半夜断线 | 第二天早上才发现一晚上没网 |

### 1.1 它做什么

- 常驻前台服务，按间隔（默认 60 秒）做一次**真实探测**；
- 判定断网后，向深澜门户**重新提交认证**，成功后复测一次，通了就停；
- 连续失败到阈值就**暂停一段时间**，不在无解的情况下折磨你的电池；
- 所有判定、动作、结果都写进运行日志，可以复制出来看。

### 1.2 它不做什么

- 不绕过计费、不共享账号、不做多设备互踢；
- 不改系统网络设置、不接管网卡、不写 hosts、不装证书；
- 不代理你的流量，不收集任何数据、不上报任何东西；
- 不用 WiFi 名称（SSID）判断网络——安卓拿 SSID 要定位权限，这里靠**网关网段**。

## 2. 主要功能

- **断线自动重新认证**：探测失败 → 门户 `get_challenge` → `srun_portal action=login` → 复测，全程无人值守。
- **真实探测，不看「已连接」**：3 个探测点依次尝试，按 HTTP 状态码和正文内容校验，被门户劫持的响应一律判为断网。
- **校园网边界**：按网关前两段（例如 `10.50.x.x` → `10.50.`）判断是不是校园网。手机连的家里 WiFi、流量、别人的热点，它一概不动。
- **事件驱动 + 定时兜底**：订阅 WiFi 网络事件（连上 / 断开 / 能力变化）即时检测；同时保留定时自查，防止漏事件。
- **熔断保护**：连续失败 5 次（可调）暂停 10 分钟（可调），避免密码填错时每 60 秒打一次门户。
- **两种后台模式**：常驻通知的前台服务，或不带通知的精确闹钟；按需选。
- **开机自启**：重启后自动恢复守护（`BOOT_COMPLETED` / 应用更新后也恢复），被系统拦截时引导你去开自启动。
- **手动三连**：立即检测 / 立即重连 / 测试登录，随时验证配置对不对。
- **账号与设置持久化**：改完即存，重启不丢；密码经 Android Keystore 加密存储。
- **统计**：今日断网次数、累计检测次数、上次断网与恢复时间。
- **运行日志**：内存保留最近 400 行，文件按 256 KB 轮转，可一键复制 / 清空。
- **极简体积**：单 APK 约 158 KB，无任何第三方依赖，也不用 Gradle 构建。
- **通知随状态变化**：在线「正常」、断线「正在重连」、暂停「已暂停」、通知被关都会显示。

## 3. 先看它适不适合你

### 3.1 支持情况

| 项目 | 情况 |
| --- | --- |
| 系统 | Android 10+（`minSdk 29`，`targetSdk 34`） |
| 认证系统 | **深澜 SRun**（`/cgi-bin/get_challenge`、`/cgi-bin/srun_portal`） |
| 判定依据 | 网关网段，不依赖 SSID、不需要定位权限 |
| 不适用 | 锐捷 ePortal、Dr.COM 城市热点、802.1X 认证、PPPoE 拨号、网页验证码登录 |
| 特殊要求 | 小米 / 红米需手动开「自启动」，否则重启后不会自动跑 |

### 3.2 怎么判断你们学校是不是深澜

1. 断开后手动打开浏览器，任意网址会被跳到登录页；
2. 地址栏形如 `http://10.50.x.x/cgi-bin/srun_portal?...` 或页面标题里有「深澜」「SRun」；
3. 电脑上按 F12 看这次跳转的请求地址，含 `srun_portal` 就是。

只要看到 `srun_portal`，这个工具就能用；换了学校或校区，改一下认证服务器 IP 即可（见 [5.4](#54-换学校--换校区)）。

## 5. 使用方法

### 5.1 第一次使用（五步）

1. 手机**先连上校园网 WiFi**；
2. 打开应用，点卡片里的「**标记当前网络为校园网**」——它把当前网关的前两段记为校园网（例如 `10.50.`），显示「校园网 ✓」；
3. 填「账号 / 密码 / 认证服务器 IP」，点「**保存设置**」；
4. 点「**测试登录**」，看日志里出现 `认证成功`；
5. 点「**开始守护**」，通知栏出现常驻通知，状态变成「运行中 · 每 60 秒自检」。

| 填什么 | 从哪来 |
| --- | --- |
| 账号 / 密码 | 学校给的校园网账号（学号等），注意有些学校密码 = 身份证后六位 |
| 认证服务器 IP | 门户登录页地址栏里那个 IP，例如 `10.50.6.100`；默认值 `192.168.199.22` 是原作者学校的，**必须改** |
| 认证接口编号 `ac_id` | 一般就填 `1`，登不上再对照登录页 URL 里的 `ac_id=` |

填完可以先点「立即重连」验证一遍，成功后再开守护。

### 5.2 面板上的操作

| 按钮 | 作用 |
| --- | --- |
| 立即检测 | 走一次完整探测，不管是否校园网；只报告结果 |
| 立即重连 | 探测失败时立刻发起认证（**会跳过熔断暂停**） |
| 测试登录 | 只做一次认证请求，用来看账号密码 / 服务器 IP 对不对 |
| 开始守护 / 停止守护 | 启停后台服务；关闭后不再自动检测 |
| 标记当前网络为校园网 | 记录当前网关网段；再点一次变成「取消标记」 |
| 清除已识别的校园网 | 清空所有标记，换学校时用 |
| 高级设置 ▾ | 展开自动检查间隔、失败阈值、暂停时长、`ac_id`、常驻通知开关 |
| 电源优化设置 | 跳到系统页面，关掉对本应用的电池优化（小米 / OPPO 必做） |
| 自启动与省电设置 | 跳系统设置，手动开自启动权限 |

### 5.3 两种后台模式

| 模式 | 怎么跑 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 常驻通知（默认） | 前台服务，通知栏一条常驻通知 | 不容易被系统杀 | 通知栏多一行 |
| 关闭常驻通知 | 前台服务 + 精确定时闹钟兜底（无精确闹钟权限时退化为普通闹钟） | 通知栏干净 | 系统可能杀掉服务，检测会被拉长到分钟级 |

常驻通知开着更稳。真的不想看通知，再把高级设置里的开关关掉。

### 5.4 换学校 / 换校区

1. 点「清除已识别的校园网」；
2. 在新网络的登录页里找到认证服务器 IP，改「认证服务器 IP」并保存；
3. 点「标记当前网络为校园网」，再「测试登录」。

同一校区换个教学楼、换个 IP 段也没关系：标记是按网关前两段存的，同网段全算。

### 5.5 统计与日志

- 统计区显示：今日断网 N 次 / 累计检测 N 次 / 上次断网时间 / 上次恢复时间；
- 日志区默认显示最近 3 行，点「展开全部」看 400 行，点「复制」整段进剪贴板（出问题时就复制这个）；
- 网络一直正常时，日志大约每 5 分钟才记一条「在线」，不会刷屏。

## 6. 权限说明

申请 8 个权限，全部是明面上的用途，没有定位、没有存储、没有通讯录：

| 权限 | 用途 |
| --- | --- |
| `INTERNET` | 探测外网、向门户提交认证 |
| `ACCESS_NETWORK_STATE` | 判断当前是 WiFi 还是流量、拿网关 IP |
| `POST_NOTIFICATIONS` | 常驻通知与结果提示（Android 13+ 需运行时同意） |
| `FOREGROUND_SERVICE` | 把守护放进前台服务，避免被系统回收 |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14 要求的前台服务类型声明 |
| `RECEIVE_BOOT_COMPLETED` | 开机后自动恢复守护 |
| `SCHEDULE_EXACT_ALARM` | 关闭常驻通知时用精确闹钟兜底，精度到分钟 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 打开系统的「电池优化」设置页，让你手动关掉限制 |

**为什么没有定位权限**：拿 WiFi 名称（SSID）在新版安卓上必须给定位权限。这个工具用网关 IP 前两段判断校园网，不需要 SSID，所以也不需要定位，装的时候不会弹「是否允许获取位置」。

## 7. 它什么时候才工作

### 7.1 什么时候触发

| 触发源 | 说明 |
| --- | --- |
| 网络事件 | 订阅当前 WiFi 网络：连上后 3 秒、断开后 2 秒、验证状态变化后 2.5~5 秒各触发一次 |
| 定时自查 | 守护开启后每「自动检查间隔」秒（默认 60，可调 30~3600）跑一次 |
| 手动 | 点「立即检测」「立即重连」「测试登录」 |
| 开机 | 重启完成、应用更新后自动恢复守护 |

所有触发共用同一个检测入口，内部有 8 秒最小间隔（3.0.1 起固定，不可改），防止事件风暴把门户打爆。

### 7.2 探测点与校验

依次尝试，任意一个判定「通」就立即返回：

| 探测点 | 判定为通 |
| --- | --- |
| `http://connect.rom.miui.com/generate_204` | HTTP 204 |
| `http://www.gstatic.com/generate_204` | HTTP 204 |
| `http://www.msftconnecttest.com/connecttest.txt` | HTTP 200 且正文含 `Microsoft Connect Test` |

规则：不跟随重定向（302 到门户就是断网）、正文超时或异常都算失败。三个点全失败 → 判定断网。

### 7.3 校园网边界

- 只有**已标记**的校园网网段才会自动认证；
- 未标记时（面板显示「已识别的校园网：（还没标记）」）不会自动动作，只做探测；
- 连的是流量、家里 WiFi、别人的热点 → 状态显示「不是校园网（不会自动重连）」，什么都不做；
- 拿不到网关（读不到网络信息）时也不动作，只写日志。

**注意**：如果从来没标记过任何校园网、而网关又是可读的，它会把当前网络当作校园网处理（为了开箱可用）。想严格限制，就先标记一次；只想手动用的，把守护关掉即可。

## 8. 恢复流程

### 第 1 步：判定边界

读当前 WiFi 的网关 IP，取前两段，和已标记的校园网比对。不在校园网内 → 记录并结束。

### 第 2 步：探测

3 个探测点依次请求，每个连接 5 秒、读取 5 秒超时。任意一个通 → 记「在线」并结束。

### 第 3 步：重新认证

按深澜 SRun 协议来一遍：

1. `GET /cgi-bin/get_challenge?callback=cb&username=…&ip=…` 拿 `token`；
2. 用 `token` 做 **XXTEA** 加密，拼出 `info` 参数（用户名、密码、IP、`ac_id`、`n=200`、`type=1` 等）；
3. `HMAC-MD5(token, 密码)` 得到 `password`，再对 `token+username+password+ac_id+ip+n+type+info` 做 SHA1 得到 `chksum`；
4. `GET /cgi-bin/srun_portal?callback=cb&action=login&…`，看返回的 `ecode`：`0` / `ok` / `ip_already_online_error` 视为成功。

### 第 4 步：复测

认证成功后再探测一次，通了记「恢复成功」并更新统计；没通记失败，累计到阈值进入熔断。

### 8.1 熔断

| 项 | 默认 | 含义 |
| --- | --- | --- |
| 连续失败几次后暂停 | 5 | 连续失败达到次数就停手 |
| 暂停多久 | 600 秒 | 暂停期间只做探测，不提交认证 |

暂停到期自动恢复。点「立即重连」可以跳过暂停立刻重试（手工操作不受熔断限制）。

### 8.2 什么情况下它明确不动

- 账号为空 / 密码为空 / 认证服务器 IP 为空 → 面板会提示，不会发请求；
- 密码解密失败（重装、系统重置后密钥失效）→ 提示「密码已失效，需重新输入」；
- 当前不是已标记的校园网；
- 熔断暂停期内（除非手动点重连）。

## 10. 设置项

存在应用私有 `SharedPreferences`（`cng_guard`）里，密码单独加密存放。

| 键 | 默认值 | 含义 |
| --- | --- | --- |
| `user` | 空 | 校园网账号 |
| 密码（加密存放） | 空 | 密文存在 Keystore 保护的 AES-256-GCM 里 |
| `host` | `192.168.199.22` | 认证服务器 IP，**换成你学校的** |
| `acid` | `1` | 认证接口编号 `ac_id` |
| `period` | `60` | 自动检查间隔（秒），范围 30~3600 |
| `min_interval` | `8` | 两次检测最小间隔（秒），内部固定，界面不可改 |
| `max_fail` | `5` | 连续失败多少次后暂停，范围 1~99 |
| `cooldown` | `600` | 暂停时长（秒），范围 0~86400 |
| `only_campus` | `true` | 只在已标记校园网内自动认证 |
| `notify` | `true` | 常驻通知开关 |
| 其他 | — | 已标记网段列表、今日断网次数与统计时间戳、初始化标记 |

数字项填错会被自动夹到合法范围，不会崩。

## 11. 安全与隐私

### 11.1 密码怎么存

- 用 `AndroidKeyStore` 生成一把 AES-256-GCM 密钥（别名 `cng_guard_key`），密钥不出系统安全区；
- 密码加密后存成 Base64 字符串，只有本应用能解密；
- 重装应用或系统重置会让密钥丢失，此时面板提示「密码已失效」，重新输入一次即可；
- 清单里 `android:allowBackup="false"`，不参与系统备份。

3.0.1 起**发布包不含任何预填账号密码**，源码里的默认账号与默认密码都是空串。

### 11.2 联网行为

只向三类地址发请求，没有别的：

1. 三个探测点（miui / gstatic / msftconnecttest）；
2. 你自己填的认证服务器 IP；
3. 没了。

没有统计 SDK、没有崩溃上报、没有广告、没有远程配置。

### 11.3 权限最小化

见 [6. 权限说明](#6-权限说明)。不申请定位、存储、通讯录、电话、短信、摄像头、麦克风。

### 11.4 明文 HTTP

`android:usesCleartextTraffic="true"` 是必需的：校园网门户和探测点都是 `http://`。这也意味着认证请求在局域网内是明文传输的（载荷里的密码已加密）——同一局域网内被嗅探属于校园网本身的限制，不是本工具引入的。

### 11.5 已知默认值

`host` 默认 `192.168.199.22`，是原作者学校门户的 IP，**不会自己变**。你装完必须改成自己学校的，否则一定认证失败。

## 12. 常见问题

**Q：会不会和学校客户端冲突？**
A：不会。它只是在你自己的账号上重新登录一次，和官方客户端走同一个门户接口。同时在线可能互相踢，建议只开一个。

**Q：检测次数一直在涨，但它什么都没做？**
A：正常。探测通过就只记一条「在线」，只有断网才动认证。网络正常时它就是个安静的计时器。

**Q：面板显示「校园网 ✓」，可实际上没网？**
A：说明网段标记对了，但认证没过。点「立即重连」，然后看日志里的 `ecode`——常见的是密码错或 `ac_id` 不对。

**Q：小米 / 红米重启后没自动跑？**
A：系统拦了自启动。到「设置 → 应用 → 校园网守护 → 自启动」打开，再把电池优化设为「无限制」。

**Q：通知栏那条通知能去掉吗？**
A：能，高级设置里关掉「常驻通知」。但系统可能因此杀掉服务，检测会变慢。

**Q：能自己连 WiFi 吗？**
A：不能。安卓从 10 起就不让第三方应用自动连 WiFi，本工具只负责「网已连上但没认证」这一段。

**Q：为什么读不到 WiFi 名称？**
A：不用读。判断校园网靠网关网段，不需要 SSID，也就不需要定位权限。

**Q：改了密码之后一直失败？**
A：点「测试登录」单独验证一次；还失败就核对 `host`（认证服务器 IP）和 `ac_id`。

**Q：怎么彻底卸载？**
A：先点「停止守护」，再到系统设置里卸载。设置和数据随卸载一起清掉，Keystore 里的密钥也会被系统删除。

**Q：日志在哪？**
A：就在面板最下面的「运行日志」，点「复制」拿完整 400 行。文件版日志在应用私有目录（未 root 的手机看不到），一般不必要。

## 14. 自己打包 APK

### 14.1 需要什么

- Linux 环境（Windows 上可用 WSL / Debian 容器）；
- JDK 17（`javac`、`keytool`、`java`）；
- Android 构建小工具：`aapt`、`zipalign`、`apksigner`（来自 build-tools）；
- `android.jar` 与 `d8.jar`（R8），默认放在 `/opt/cng-toolchain`，可用 `CNG_TOOLCHAIN` 环境变量改；
- `python3`（第 4 步合成 APK 用）。

### 14.2 构建流程

`sh build.sh` 会依次执行：

| 步骤 | 内容 |
| --- | --- |
| 0/7 | 把 `src`、`res`、清单复制到 `/tmp/cngbuild`（用 `/tmp` 是因为手机内部存储是 FUSE，JVM 读不了） |
| 1/7 | `aapt package` 生成基础 APK |
| 2/7 | `javac` 编译全部 Java（`-source 8 -target 8 -g:none`，不带调试信息） |
| 3/7 | `R8 --release --min-api 29` 裁剪并转 `classes.dex`（keep 四个入口类） |
| 4/7 | `python3` 把 `classes.dex` 塞进 APK |
| 5/7 | `zipalign -f 4` 对齐 |
| 6/7 | `apksigner` 签名并 `verify` |
| 7/7 | 拷回 `dist/campus-guard-v3.0.1.apk` |

### 14.3 签名

`build.sh` 第一次跑会用 `keytool` 自动生成 `keystore.jks`（口令 `campusguard`，仅测试用），之后复用。**自己发布请换成自己的 keystore，并且不要把 `keystore.jks` 提交进仓库**——本仓库的 `.gitignore` 已排除它和 `*.apk`。

### 14.4 跑单测

```sh
sh test/run.sh
```

在桌面 JVM 上跑，不需要手机：`NetTest`（探测校验）、`LogicTest`（节流 / 熔断 / 状态机）、`SrunTest`（协议编码与 chksum），共 46 处断言。

## 15. 验收与已知限制

### 15.1 已验证

- 编译、R8、签名、zipalign 全流程通过；`apksigner verify` 通过；
- 46 处逻辑断言全部通过（`sh test/run.sh`）；
- 界面在 Android 10 及以上机型能正常打开与布局；
- 手动「测试登录」「立即重连」在真实深澜门户上认证成功。

### 15.2 未验证 / 已知限制

- **长时运行未做数小时实测**：默认 60 秒一次时，后台存活依赖系统策略，小米 / OPPO 必须手动放开自启动与电池优化；
- **开机自启**：只验证了正常的 `BOOT_COMPLETED` 路径，被厂商 ROM 拦截时只能靠面板提示引导用户手动设置；
- **非校园网边界**：靠网关前两段，跨校区同网段会被当成校园网；网关取不到时不动手；
- **只备案深澜 SRun**：协议里写死了 `n=200&type=1`，别的认证系统一律不适用；
- **明文 HTTP**：见 [11.4](#114-明文-http)；
- **深色模式**：跟随系统，深色下部分次要文字对比度偏弱，属于已知外观问题。
